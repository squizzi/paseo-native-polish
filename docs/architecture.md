# Architecture

## Boundaries

`index.client.tsx` registers the settings screen and Command Center action, then starts the web adapter. There is no server entry. Settings components use the public Paseo plugin UI and React Native primitives.

The public plugin API has no host-wide motion hook for existing sidebars or file trees. `client/web.ts` therefore contains a guarded DOM adapter and its minimal DOM types. Native platforms return a no-op. It does not import private React internals or patch the app bundle. All selectors target the Paseo 0.11.2 view structure.

## Capturing changes

Pointer-down on actionable controls captures layout before host gesture handlers commit. Click and keyboard activation cover other paths. Known interactive sidebar/tree rows remain eligible when RN web Pressables omit roles. Ordinary content clicks and editing Enter/Space do not capture layouts; global sidebar shortcuts remain eligible in the composer. The host's window capture shortcut handler precedes ours, stops propagation and commits sidebar state in a microtask before our window listener runs. Sidebar baselines are therefore taken on Cmd/Ctrl keydown, and repeated shortcuts under one modifier hold reuse the previous commit's baseline, but editor/terminal shortcuts are excluded. Composition events plus isComposing/keyCode 229 guards preserve the host input path. No focus, caret, selection or key events are modified. Editor/terminal internal mutations are excluded from ambient invalidation. A mutation observer and bounded frame polling catch asynchronous commits. Ambient updates use a per-frame set of dirty regions. Chat-local mutations update tools/messages without cloning workspace/project snapshots or measuring pane/tab layouts. Shell commits still discover all surfaces. Spinner leaf styles, elastic adapter style writes and ghost-only child-list mutations do not invalidate ambient layouts. Wheel bursts defer workspace snapshots until an idle rebase; virtualized membership changes during input do not look like workspace creation/removal.

Sidebars animate the actual width owner. A retained sidebar keeps its slot during exit; an unmounted Explorer gets an inert copy in that slot so adjacent panes resize. Pane, tab and reorder changes use bounded FLIP geometry. Disclosure animation watches direct membership changes; tree identity follows ancestor names and indentation rather than changing numeric row IDs. Each tree commit captures its clean destination once before FLIP, then reuses that capture for animation and the next baseline. Deep copies are bounded to 120 visible rows; exceptionally large views trade full-row animation coverage for bounded synchronous work.

Maximize/restore captures retain ownership for the full gesture, so the ambient membership observer cannot replay the same pane transition. Pane baselines exclude active parent/pane animation frames. Only outer sidebar width owners animate. Tab FLIP requires a real key-order change and uses tab-rail-relative positions; children do not get a second transition from sidebar/pane movement.

Menus preserve host-provided entrances where present. A keyframe animation or fade transition on the surface or its nearest portal wrappers marks the motion as host-owned: no second entrance is added, and a host fade transition also suppresses the exit copy. Reused portal surfaces open by gaining their role, so role changes refresh overlay membership; a docked sidebar that also carries an overlay role is excluded from this membership, since it already owns a width-based entrance/exit from the panel adapter. Exit copies have duplicate IDs and interactive media removed. They cannot receive focus or accessibility input. Newly appended message IDs fade once near the tail; initial history and virtualized remounts do not replay.

Workspace sidebar membership uses stable workspace test IDs, including mounted rows outside the viewport. Only visible rows and section headers get bounded snapshots. Creation fades in; removal uses an inert exit copy and scroll-relative FLIP positions for surviving neighbors. Initial list mounts, section toggles and active parent/sidebar animations rebase without row motion. Project trailing creation buttons are excluded from disclosure capture. Workspace row motion shares the sidebar preference.

Row order and section identity also detect pin/unpin and status migration when membership stays unchanged. Horizontal and vertical FLIP positions survive keyed row remounts. A new structural commit can interrupt existing row motion from its current visual position; animation-generated mutations do not restart it. Fully visible project groups get one entrance/exit owner, while clipped groups use visible rows and headers. A group containing a migrating workspace keeps that row under its own motion owner. Filter/grouping gestures rebase instead of looking like project deletion/creation.

## Motion lifecycle

Markdown file previews use an RN ScrollView without a test ID. The elastic adapter finds the nearest vertical scroll ancestor of `markdown-preview-frame`, within `workspace-file-pane`, rather than targeting every scrollable file-pane child. That owner joins the existing boundary lifecycle and gesture handling. Input inside a nested code/detail scroller stays excluded. Switching modes or closing a preview restores its boundary styles during the next surface refresh.

Editable and read-only Source views for all text file types use `file-source-editor .cm-scroller` within the file pane. CodeMirror has coordinated content, gutter, cursor and selection layers, without an RN content wrapper. The adapter translates the complete scroller inside the existing clipped editor host; it does not reparent content, translate individual code lines, alter overflow or write scrollTop. Scroll metrics are checked before keeping any feedback. Pointer/keyboard input, beforeinput and compositionstart reset translation before editor handlers consume input, and wheel input with held buttons is ignored. A CodeMirror root mounting into `file-source-editor` invalidates only elastic surface discovery; token/caret/selection mutations remain excluded from global motion scans.

Sandboxed HTML documents have their own event tree and are not included by the parent-document adapter. Images use ZoomableViewport's zoom/pan gestures, not a vertical document scroller. Unsupported/binary/loading views have no document scrolling to adapt.

`client/elastic-scroll.ts` handles vertical boundary input for the known chat/workspace/file/changes scroll roots using passive listeners. Supported Apple-platform browsers retain compositor overscroll with `contain`; Electron is excluded because its native bounce requires the main-process `scrollBounce` option. The fallback leaves scrollTop and native inertia under the host's control, skips nested code/detail scrollers and composes individual CSS translate with existing virtualizer transforms. Translated descendants are clipped inside the unchanged scroll content box to avoid extending scrollHeight. Feature/metric guards fail closed if the DOM or host styles differ. Pull follows input directly through a resisted distance curve; its extent depends on viewport height (36–100 px). Only release uses a critically damped spring, after a cadence-dependent 40–120 ms wheel-input gap or touch release. Momentum release bypasses this hold. Each wheel gesture retains a terminal release latch: sustained decay, spring return or cancellation closes it, and amplitude fluctuations cannot reopen it. A fling reaching an edge gets one displacement, then returns independently of its remaining tail. A 240 ms quiet gap or direction reversal starts another gesture; ignored tail events update the timestamp so they cannot repeatedly renew the pull. At a released boundary, line/page wheel impulses, spaced fresh pixel impulses or sustained renewed pressure above the tail low point can begin another pull without waiting for the old tail to expire. A continuous tail spike alone cannot reopen the latch: multiple meaningful non-decaying samples must confirm renewed pressure. Their input is retained and resumes from the visible offset. Event cadence is smoothed so sparse non-momentum input can remain held without changing the spring timing. DOM events do not expose the native momentum phase, so gesture segmentation remains approximate. New input resumes from the visible displacement. Active rebound suppresses ambient entrances; settling rebases the normal layout snapshots. Content changes, real scrolling and interaction cancel the feedback. Original boundary, clip, translate and custom-property values are restored without overwriting host changes.

Window blur/document hiding suspends ambient scans and animations, cancels capture/scroll/passive scheduling, restores boundary feedback and releases detached baseline DOM. Blur checks document.hasFocus after the focus transfer completes, so focus entering a nested HTML frame does not suspend the whole adapter. On focus/visibility return, one frame rebases without replaying background entrances/exits; input may consume that rebase first. A focused-document pointer move can also reconcile stale suspension without moving focus. The observer remains installed but returns without scanning while suspended. This affects only plugin work; it does not stop host rendering or daemon activity.

Preferences use a small reactive store and client-local storage. Reduce Motion is observed live. Dragging, scrolling, preference changes and teardown cancel active animations. Cleanup removes temporary styles, inert copies, injected CSS, DOM markers, observers, timers and event listeners.

## Compatibility

The manifest limits the plugin to Paseo 0.11.x with a minimum of 0.11.2. The adapter was developed against 0.11.2. A compatible semver range does not establish that every host DOM revision has been reviewed. Inspect changed selectors and their retained/unmounted lifecycle before widening the range.

## Desktop edge preview

`client/edge-peek.ts` uses the host's DOM controls (`menu-button`, `workspace-explorer-toggle`) to mount and activate real sidebars. It never clones interactive content or edits React internals. Before the control is activated, a body marker takes the retained left width owner or the Explorer resize-handle's following dock out of flex layout with fixed positioning. The latter selector applies in the first React commit, before layout observation. Existing canvas geometry remains unchanged. Host visibility changes temporarily while the preview is present; the control is activated again to restore closed state on exit. Source controls and DOM ownership remain intact.

Only mouse/fine-hover input on desktop can enter, after a 180 ms hold within a 7 px edge zone below the titlebar. Exit has 260 ms grace and defers for native portal menus, drag input and a focused sidebar input. Escape latches the edge until the cursor leaves it. A regular toggle activation first restores the hidden state so the subsequent host activation can open its normal dock. Blur, document visibility, resize, preference changes and teardown restore visibility and remove markers, styles, timers, observers and listeners. A failed/detached control never toggles a new workspace's unrelated visibility.

Sandboxed HTML previews use a separate event tree, so their pointer moves never reach the parent-document listener. Two transparent fixed gutters reserve the 7 px activation edges above frame content, below the sidebar overlay; only available hidden desktop sides accept pointer input. They have no tab stop or accessibility content and occupy no layout width. This trades mouse access to the underlying page's outermost 7 px for reliable hover without changing the frame sandbox, injecting preview scripts or forwarding synthetic clicks. Opening still requires document focus. Entering a frame invalidates the last parent pointer coordinates and starts the close grace period; nested-frame focus is distinguished from actual window blur. Chrome membership changes refresh gutter availability, while unrelated streaming mutations do not scan layout. The adapter has no active-host or workspace-location restriction.

Frame entry clears parent pointer coordinates on both pointerout and the following iframe pointerover, so the latter cannot restore a stale position inside the sidebar's tolerance zone. When relatedTarget is null, host-document hit-testing distinguishes a frame crossing from an ordinary DOM removal. A direct pointerleave listener on the real sidebar root also starts the existing exit grace period without relying on events inside the sandbox. Root listeners are removed with their preview owner; frame content is never accessed or changed.

The preview slide owns its CSS animation. Global captures stay suppressed while the preview is present; elastic rebound remains active for the preview's lists. Closing retains fixed positioning until the host dock is actually hidden/unmounted, rather than treating aria-expanded as a completed layout commit. Two subsequent layout frames rebase geometry before ordinary motion resumes. Explicit dock toggles/shortcuts hand ownership back immediately so regular layout transitions remain available. Reduce Motion removes the slide while retaining the feature. All timing, selectors and mounting assumptions are internal DOM compatibility details scoped to Paseo 0.11.2. Static checks do not confirm visual behavior; interaction checks remain manual.

Connected daemons each evaluate a client bundle, but the window has one DOM motion adapter. `client/motion-runtime.ts` leases that ownership to the newest connected plugin version and hands it over when its host disconnects or reloads. The window also shares the preferences store, so settings opened through any host control the active adapter. Per-host settings and command contributions retain their own normal registration lifecycle. Older releases without this coordination must also be updated to prevent duplicate animation owners.
